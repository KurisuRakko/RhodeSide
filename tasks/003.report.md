### 2.3 下拉（Base UI Select）的坑与修法

第一次跑挂在「点模型下拉切回荒芜拉普兰德」：`Locator.click: Timeout 30000ms`，报
`<div role="presentation" data-base-ui-inert=""> ... intercepts pointer events`。
根因有两个，都出在测试脚本自己、不是页面 bug：

1. Base UI 的 Select 弹层关闭后节点**仍留在 DOM 里**，`page.locator("[role=option]")` 会命中已关闭的旧选项
   （第一次跑就把模型下拉的选项误当成了「模型组」的选项）。
2. 选项点完到弹层真正关闭之间有个过渡，此时 Base UI 会挂一层 `data-base-ui-inert` 遮罩挡住外面的点击。

修法：只查**当前可见**的弹层 `[role=listbox]:visible [role=option]`，并在「开 → 选 / 关」之间
用 `wait_until` 等可见弹层数量归零。改完 38 项一次全过。

### 5.2 `hit`（像素级判定）与坐标换算

**换算方法**（脚本里 `hit_pick.conversion` 原样记录）：

- 消息坐标是 **CSS px，原点在画布左下角、y 向上**（和 AppKit 窗口坐标一致，`main.ts` 注释也这么写）。
- 画布快照 PNG 的坐标是 **像素，原点在左上角、y 向下**；`canvas.width/height` 是设备像素，
  `css = 设备像素 / dpr`（本页 dpr=1）。
- 设画布高 `H`（像素），取到的不透明像素为 `(xc, yc)`，则：
  - `x_css = (xc + 0.5) / dpr`（取像素中心，+0.5）
  - `y_css = (H - 1 - yc + 0.5) / dpr`（先上下翻转 `H-1-yc`，再取像素中心）

**选点保证落在实心处**：不只找 `alpha>200` 的点，还要求它周围 `±3*dpr` 的方形邻域里每个像素 `alpha>24`
（与 `main.ts` 的 `hit()` 读回窗口一致），避免选到边缘抗锯齿像素导致假阴性。

| 用例 | 画布像素 | 换算后消息 (x, y) | console 回包 | 结果 |
|---|---|---|---|---|
| 不透明实心点 | `(182, 255)`，邻域 alpha 全 >24 | `(182.50, 144.50)` | `{type:'hit', id:1, x:182.5, y:144.5, inside:true}` | 过 |
| 四角透明点 | `(0, 0)`，alpha=0 | `(0.50, 399.50)` | `{type:'hit', id:1, x:0.5, y:399.5, inside:false}` | 过 |

（`x_css=(0+0.5)/1`；`y_css=(400-1-0+0.5)/1=399.5`，对应画布左上角。）

## 6. 判据说明

1. **设置页元素**：用固定选择器（`h1.rs-title`、`.rs-badge`、`.rs-section__title`、`.rs-card__title`、`.rs-item__*`），
   文本做空白归一化后比较。
2. **选中态**：分段选择优先读 `[role=radio][aria-checked="true"]`，回退 `[data-checked]`；开关读 `[role=switch]` 的
   `aria-checked`。都读到了真实属性，不是看颜色。
3. **下拉**：只认当前可见的 `[role=listbox]:visible [role=option]`，避开 Base UI 关闭后残留的节点。
4. **深色对比度**：WCAG 相对亮度公式，背景取元素最近的非透明祖先 `background-color`。
5. **`hit`**：邻域实心判据 + 半像素中心换算（§5.2），与 `main.ts` 的 `readPixels` 窗口对齐。
6. **`pause`/`fps`**：画布 `toDataURL('image/png')`（`preserveDrawingBuffer:true`，真 alpha）逐字节比较 / md5 去重。

## 7. 观察 / 备注（都不是本次要改的 bug，供 Claude 定夺）

1. **页头「浏览器预览」出现两次**：`bridge.ts` 的假原生层把 `version` 设成 `'浏览器预览'`，
   同时 `!native` 又加一个「浏览器预览」徽标，所以副标题里 `浏览器预览` 紧跟一个同字样的徽标。
   预览模式下只是观感重复；原生里 `version` 会是真实版本号，不会撞。要消掉的话让假原生层的
   `version` 改成别的（比如 `'预览'`）即可。
2. **预览里卡片状态永远「载入中…」**：假原生层的 `pets[].loaded` 恒为 `null`，所以桌宠卡片不显示
   `行为 · 时装 · 模型组`。这是浏览器预览的固有局限（没有真的渲染进程回报 `loaded`），不是 bug；
   但「时装」默认值因此取的是 `sets[0].outfit` 而不是当前载入的时装。
3. **切换模型后「模型组」下拉显示占位符「—」**：`patch({model, outfit:null, group:null})` 把 group 清空后，
   界面不会自动补回默认组，需要用户再选一次。`pet.html` 的 `pickSet()` 会兜底到 `基建`，所以桌宠行为正常，
   只是设置页上看起来是空的。属于 UX 小瑕疵，不影响功能。
